# KEMEX-HUB

منصة عربية لإدارة مكتبة المحتوى وتجهيز الكابشنات ومتابعة النشر على صفحة Facebook من مكان واحد. الواجهة مبنية باستخدام Next.js وReact، وقاعدة البيانات الوحيدة المستخدمة هي **Neon PostgreSQL**.

## المزايا الحالية

- موقع تعريفي عام مع صفحات تسجيل الدخول وإنشاء الحساب.
- تسجيل أول حساب مرة واحدة عند تهيئة قاعدة فارغة، ثم إنشاء رموز دعوة عشوائية من داخل لوحة التحكم؛ كل رمز صالح لاستخدام واحد ولمدة 7 أيام. كلمات المرور تُخزن باستخدام `scrypt` والجلسة في ملف تعريف ارتباط `HttpOnly`.
- لوحة تحكم بمؤشرات للمحتوى النشط والمتاح للنشر وسجل النشر الأخير.
- مكتبة لإضافة الصور والفيديوهات والريلز مع كابشنات متعددة، وتعديل الكابشنات أو تعطيل المحتوى أو حذفه.
- النشر اليدوي أو من خلال جدولة خارجية، مع تخزين نتيجة العملية.
- تنبيهات Telegram اختيارية.
- تصميم RTL متجاوب للموبايل والتابلت والكمبيوتر.

> **مهم:** هذا المشروع مساحة عمل واحدة مشتركة للفريق، وليس نظام SaaS متعدد العملاء. لا تشارك رمز الدعوة إلا مع الأشخاص المسموح لهم بإدارة محتوى مساحة العمل.

## التقنيات

- Next.js 15 / React 19 / TypeScript
- Neon Serverless PostgreSQL عبر `@neondatabase/serverless`
- Vercel للاستضافة
- Meta Graph API للنشر على Facebook
- GitHub Actions للجدولة والنشر التلقائي

قاعدة البيانات الوحيدة المستخدمة في الكود هي Neon، ولا توجد أي حزمة قاعدة بيانات أخرى ضمن الاعتماديات.

## 1. إعداد Neon

1. أنشئ مشروع PostgreSQL على Neon.
2. افتح SQL Editor وشغّل محتوى `neon/schema.sql` لإنشاء الجداول المطلوبة.
3. انسخ **pooled connection string** من Neon.
4. استخدمه في متغير `DATABASE_URL` على Vercel. لا تضعه في متغير يبدأ بـ `NEXT_PUBLIC_` ولا تستخدمه في المتصفح؛ الاتصال يتم على الخادم فقط.

## 2. متغيرات البيئة

استخدم `.env.example` كقائمة مرجعية. أضف المتغيرات التالية إلى إعدادات Vercel لكل بيئة تحتاجها:

| المتغير | مطلوب؟ | الغرض |
| --- | --- | --- |
| `DATABASE_URL` | نعم | اتصال Neon pooled PostgreSQL |
| `SESSION_SECRET` | اختياري | سر مستقل لا يقل عن 32 بايت. عند عدم ضبطه، يُشتق مفتاح جلسات ثابت من `DATABASE_URL` على الخادم |
| `FB_PAGE_ID` | للنشر | معرّف صفحة Facebook |
| `FB_PAGE_TOKEN` | للنشر | رمز وصول صفحة Facebook |
| `CRON_SECRET` | عند استخدام الجدولة | سر التحقق من طلب النشر المجدول |
| `SITE_URL` | GitHub Actions فقط | عنوان Vercel الكامل، مثل `https://kemex-hub.vercel.app` |
| `TELEGRAM_BOT_TOKEN` | اختياري | رمز بوت التنبيهات |
| `TELEGRAM_CHAT_ID` | اختياري | المحادثة المستقبلة للتنبيهات |

لا تحتاج إلى إنشاء `REGISTRATION_INVITE_CODE` أو إضافته إلى Vercel؛ إذا كان موجودًا من إعداد سابق، يمكنك حذفه لأنه لم يعد مستخدمًا. عند أول تشغيل على قاعدة `user_accounts` فارغة، يمكن إنشاء الحساب الأول مرة واحدة دون رمز. بعد ذلك، ينشئ العضو المسجّل من لوحة التحكم رمزًا عشوائيًا صالحًا لاستخدام واحد لمدة 7 أيام؛ لا يحفظ Neon إلا بصمة الرمز، ويظهر الرمز الخام مرة واحدة عند إنشائه.

`SESSION_SECRET` أيضًا لم يعد مطلوبًا لتشغيل التسجيل. للحفاظ على الجلسات عبر مثيلات Vercel، يشتق التطبيق مفتاحًا ثابتًا بخوارزمية HMAC من `DATABASE_URL` إذا لم يوجد `SESSION_SECRET`. يمكن ضبط سر مستقل اختياريًا؛ وإذا تغيّر `DATABASE_URL` دون وجود `SESSION_SECRET` مستقل، ستنتهي صلاحية الجلسات الحالية ويحتاج المستخدمون إلى تسجيل الدخول مجددًا.

## 3. أول حساب أو حسابات إضافية

يوفر المشروع طريقتين:

- **بدء المنصة:** إذا لم يوجد أي مستخدم في قاعدة البيانات، يمكن لأول حساب التسجيل من `/register` دون رمز. هذه خطوة تهيئة تُتاح مرة واحدة فقط؛ نفّذها عند تجهيز الموقع وقبل مشاركة رابطه.
- **دعوة أعضاء إضافيين:** بعد تسجيل الدخول، افتح لوحة التحكم وأنشئ رمز دعوة جديدًا، ثم شاركه مع العضو المقصود. الرمز أحادي الاستخدام وينتهي بعد 7 أيام.
- **إنشاء الحساب من الطرفية:** شغّل `npm run create-user` محليًا بعد وضع `DATABASE_URL` في `.env.local`. إذا استخدمت هذه الطريقة أولًا، يعتبر التطبيق التهيئة مكتملة تلقائيًا، ثم يجب إنشاء دعوات من لوحة التحكم للمستخدمين الإضافيين.

جميع الحسابات المسموح بها تعمل داخل مساحة العمل المشتركة نفسها. لا تضف مستخدمين غير موثوقين إلى هذا المشروع.

## 4. إعداد Facebook والنشر

1. أضف `FB_PAGE_ID` و`FB_PAGE_TOKEN` إلى إعدادات Vercel بعد تجهيز صلاحيات Meta Graph API اللازمة للصفحة.
2. ارفع الوسائط إلى استضافة توفر رابطًا مباشرًا عامًا للصورة أو الفيديو، ثم استخدم الرابط في مكتبة المحتوى. التطبيق لا يخزن ملفات الوسائط.
3. أضف ثلاثة كابشنات على الأقل للمحتوى الذي تريد تدويره.
4. اختبر النشر اليدوي من داخل الموقع قبل تفعيل أي جدولة.
5. إذا فعّلت التنبيهات، أضف `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID`.

روابط مشاركة Google Drive غالبًا ليست روابط وسائط مباشرة يمكن لـFacebook تنزيلها. وتحتاج صلاحيات Meta وتوكن الصفحة إلى إدارة وتجديد من حساب Meta المالك.

## 5. التشغيل المحلي

يتطلب Node.js 20 أو إصدارًا متوافقًا مع إصدار Next.js المستخدم.

```bash
npm ci
cp .env.example .env.local
# املأ قيم البيئة في .env.local
npm run dev
```

لإنشاء حساب من الطرفية:

```bash
npm run create-user
```

لفحص نسخة الإنتاج محليًا:

```bash
npm run build
npm start
```

## 6. تفعيل النشر المجدول

المشروع يتضمن `.github/workflows/publish.yml` ويشغّل طلب النشر يوميًا الساعة 10:00 و17:00 UTC، كما يمكن تشغيله يدويًا من تبويب Actions. لتفعيله:

1. في GitHub افتح **Settings → Secrets and variables → Actions**.
2. أضف `SITE_URL` = عنوان الموقع على Vercel من دون `/` في النهاية.
3. أضف `CRON_SECRET` بالقيمة نفسها المستخدمة في إعدادات Vercel.
4. تأكد من إعداد `FB_PAGE_ID` و`FB_PAGE_TOKEN` في Vercel، ثم اختبر عملية النشر يدويًا من الموقع قبل الاعتماد على الجدولة.

## 7. النشر على Vercel

1. ارفع ملفات المشروع إلى مستودع GitHub.
2. استورد المستودع في Vercel.
3. أضف متغيرات البيئة المطلوبة قبل أول نشر.
4. استخدم أمر البناء الافتراضي `npm run build`.
5. بعد النشر افتح `/`, ثم جرّب `/login`, و`/register`, وبعد تسجيل الدخول تُفتح لوحة `/dashboard`.

إذا فشل البناء، راجع أول TypeScript أو build error في سجل Vercel؛ تحذيرات إعدادات npm غير المدعومة لا تعني وحدها فشل البناء.

## ملاحظات تشغيلية وأمنية

- مسارات API التي تعدّل المحتوى أو الإعدادات تتحقق من جلسة الدخول.
- ملفات الاتصال بقاعدة البيانات واستخدام `scrypt` تعمل على الخادم فقط.
- لا يحتوي المشروع على استعادة كلمة المرور عبر البريد؛ عند نسيانها، استخدم إجراء إداري آمن لتحديث بيانات الحساب في قاعدة البيانات أو أضف تدفق استعادة موثّقًا قبل الاعتماد عليه في الإنتاج.
- لا توجد رسوم بيانية تحليلية مرتبطة بواجهات Facebook Insights في هذه النسخة؛ المؤشرات الحالية مبنية على سجلات المحتوى والنشر المخزنة في Neon.
